# Опис проєкту: Baraholka NaUKMA

## Ідея проєкту
Baraholka NaUKMA - сайт оголошень, де студенти й співробітники Могилянки продають і купують вживані та нові речі одне в одного: підручники, техніку, меблі для гуртожитку, одяг тощо. Зараз такі оголошення розкидані по чатах у Telegram і групах у соцмережах, де важко щось знайти вже за тиждень.

Сайт дає єдине місце з пошуком і фільтрами по категоріях, де продавець публікує оголошення з фото та ціною, а покупець знаходить потрібне й домовляється про зустріч напряму. Оплата й доставка - поза сайтом, система тільки зводить людей і показує оголошення.

## Ролі користувачів
- **Продавець** - публікує оголошення (назва, опис, ціна, фото, категорія), редагує чи знімає їх з публікації, бачить свою історію оголошень.
- **Покупець** - переглядає й шукає оголошення, фільтрує за категорією/ціною, зберігає оголошення в обране, бачить контакти продавця для зв'язку.
- **Адмін** - модерує оголошення (видаляє заборонені/спам), керує категоріями, блокує користувачів, які порушують правила.

Один акаунт може виступати і продавцем, і покупцем одночасно - це не окремі типи реєстрації, а ролі за діями.

## Ключові функції
1. Вхід через Microsoft Entra ID з обліковим записом НаУКМА (`@ukma.edu.ua`).
2. Створення, редагування та зняття з публікації оголошення (з фото).
3. Перегляд і фільтрація оголошень за категорією, ціною, датою публікації.
4. Пошук оголошень за текстовим запитом.
5. Збереження оголошень в обране (список "мої закладки").
6. Перегляд контактів продавця для зв'язку поза сайтом.
7. Модерація оголошень і користувачів адміном (видалення, блокування).

## Міні-ТЗ

### 1. Призначення системи
Baraholka NaUKMA розв'язує проблему розпорошених оголошень про купівлю-продаж речей між студентами й співробітниками НаУКМА: замість пошуку по десятках Telegram-чатів - один сайт із категоріями, фільтрами та пошуком, доступний лише людям з університетською поштою.

### 2. Межі системи
**Входить в обсяг семестру:**
- Автентифікація через single-tenant застосунок Microsoft Entra ID НаУКМА; локальні паролі система не зберігає.
- CRUD оголошень з фото, категоріями, ціною.
- Пошук і фільтрація оголошень.
- Обране.
- Панель модерації для адміна.

**Не входить в обсяг (свідомо поза межами):**
- Оплата всередині сайту - розрахунок лишається офлайн, між користувачами.
- Доставка чи логістика - тільки особиста зустріч, сайт цим не займається.
- Мобільний застосунок - тільки веб, адаптивний під мобільний браузер.
- Рейтинги й відгуки про продавців.
- Вбудований чат між покупцем і продавцем - контакт передається один раз, спілкування далі поза сайтом (Telegram/пошта).

### 3. Ролі користувачів і дії

- Продавець - створює/редагує/знімає оголошення, бачить свою історію 
- Покупець - переглядає, шукає, фільтрує, додає в обране, бачить контакти продавця 
- Адмін - модерує оголошення, керує категоріями, блокує користувачів

### 5. Нефункціональні вимоги
1. **Продуктивність.** Сторінка списку оголошень (20 карток) завантажується за ≤ 300 мс при 50 одночасних користувачах.
2. **Безпека/приватність.** Вхід дозволено лише для облікових записів tenant НаУКМА з підтвердженою адресою `@ukma.edu.ua`; email та контактні дані не показуються неавтентифікованим відвідувачам.
3. **Надійність.** Опубліковане оголошення не втрачається при збої сервера - дані зберігаються в PostgreSQL з транзакційним записом, а не тільки в пам'яті.
4. **Зручність використання.** Створення нового оголошення (від відкриття форми до публікації) займає не більше 5 кроків/полів для заповнення.

### 6. Припущення та обмеження
- **Стек:** React (frontend), FastAPI (backend), PostgreSQL (БД).
- **Автентифікація:** Microsoft Entra ID НаУКМА, OpenID Connect / OAuth 2.0 Authorization Code Flow; застосунок зареєстровано як single-tenant, а точний redirect URI буде додано перед інтеграційним тестуванням.
- **Хостинг:** ще не обрано остаточно.
- **Команда:** 4 студенти, семестр (вересень–грудень 2026), паралельно з іншими курсами - орієнтовно 4–6 год/тиждень на людину поза піковими дедлайнами лабораторних.
- **Дані для тестування:** реальних даних немає, оголошення й категорії для розробки - тестові/вигадані.
