# Mutation testing

## Мета

Перевірити якість тестів `ListingService`, а не лише покриття рядків.
Цей модуль містить основні бізнес-правила: фільтрацію, пошук,
перевірку власника, оновлення та зняття оголошення з публікації.

## Інструмент і запуск

Використано `mutmut 2.5.1`. Версію зафіксовано у `requirements-dev.txt`,
а область мутацій обмежено файлом `src/services/listings.py` у
`pyproject.toml`. Гілка 3.x не підходить до поточної структури проєкту,
оскільки вона відхиляє імпорти з префіксом `src.*`.

```bash
python -m pip install -r requirements-dev.txt
mutmut run
mutmut results
```

## Результати

| Етап | Всього мутантів | Вбито | Вижило | Mutation score |
| --- | ---: | ---: | ---: | ---: |
| Перший запуск | 54 | 32 | 22 | 59,3% |
| Після посилення тестів | 54 | 54 | 0 | 100% |

Перший запуск виявив, що звичайне покриття не захищало від змін:

- стандартного ліміту каталогу з 10 на 11;
- включних меж цінового діапазону;
- пошуку за описом та фільтрації за категорією;
- оновлення `description`, `price`, `contact` і `updated_at`;
- точних доменних помилок.

До `tests/test_listing_service.py` додано 4 нові тести та посилено наявні перевірки.
Загальна кількість тестів збільшилася з 37 до 41. Повторний запуск вбив всі
54 мутанти. Звичайне покриття після змін становить 98,38%.

Після об'єднання всіх змін Лабораторної 6 повний набір містить 52 тести,
а повторний запуск mutation testing для `ListingService` так само знищує
54 з 54 мутантів.

## Висновок

Mutation testing показав прогалини, яких не було видно лише за показником
line coverage. Після доданих перевірок тести фіксують не лише виконання
рядків, а й очікувану бізнес-поведінку сервісу.
