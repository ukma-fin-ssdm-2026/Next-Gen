# Підсумок взаємного огляду тест-плану

**Команда-рецензент:** B2B

## Сильні сторони

1. У плані чесно зафіксовано межі поточної реалізації та відомі прогалини.
2. Тест-кейси мають конкретні очікувані результати, HTTP-коди й вимірювані критерії.
3. Для основних компонентів визначено різні рівні тестування та відповідальних учасників.

## Зони для покращення

1. Головний ризик обходу авторизації власника був зазначений, але не мав негативного сценарію зняття чужого оголошення.
2. `TP-N02` суперечив критеріям виходу: план вимагав проходження всіх кейсів у CI, хоча навантажувальний тест був заблокований. Також не було чітко визначено, чи вимірюється UI або API, а перевірка максимуму часу кожного запиту могла давати нестабільні результати. Окремо потрібно було уточнити, що `TP-001` покриває FR-002 лише частково, без фотографій.

## Зміни після огляду

- Додано `TP-007`: не-власник отримує HTTP 403 під час спроби зняти чуже оголошення; стан і дані оголошення не змінюються.
- Додано відповідний API-тест `test_delete_foreign_listing_is_403_and_preserves_listing`.
- `TP-N02` винесено зі звичайного CI в окремий контрольований запуск.
- Уточнено об'єкт вимірювання: `GET /api/v1/listings?limit=20` із 500 активними оголошеннями, 50 одночасними користувачами та тривалістю 60 секунд.
- Критерій продуктивності змінено на `p95 ≤ 300 мс` і 0% помилок; повна перевірка React UI залишається майбутнім етапом.
- `TP-001` позначено як часткову перевірку FR-002 без підтримки фотографій.
