**Обсяг:** тестуємо реалізоване ядро маркетплейсу оголошень:
1. Створення оголошень (включно з фотографіями через `ImageStorage` та станом товару `condition`, `FR-002`);
2. Редагування власного оголошення продавцем (`FR-003`);
3. Зняття оголошення з публікації зі збереженням даних в історії (`FR-004`);
4. Історію власних оголошень продавця (`ACTIVE` і `WITHDRAWN`, `FR-005`);
5. Публічний каталог із текстовим пошуком, фільтрацією та сортуванням (`FR-006`–`FR-008`);
6. Роботу покупця з "Обраним" (`FR-009`);
7. Захист конфіденційності контактів продавця для анонімних користувачів (`SEC-002`);
8. Керування та публічний перегляд категорій оголошень (`FR-012`): публічні ендпоінти перегляду та деталей, а також адміністративне додавання, перейменування та деактивація категорій із захистом за роллю `ADMIN` (`X-Actor-Role: ADMIN` до повної інтеграції OIDC claims);
9. Виконуваний системний бенчмарк продуктивності API каталогу під конкурентним навантаженням (`PERF-001`, `TP-N02`).

Свідомо не тестуємо в цьому релізі: ще не завершену OIDC/Entra ID автентифікацію з зовнішнім IdP (покрито на рівні модульних перевірок claims), модераційне блокування користувачів (`FR-013`), клієнтський React UI та процедури аварійного відновлення PostgreSQL кластера (`REL-001`).

- Усі автоматизовані функціональні, регресійні та security-тести (`TP-001`–`TP-017`, `TP-N01`, `DT-01`–`DT-07`, AST-тести простежуваності) проходять успішно у CI;
- Виконуваний тест продуктивності `TP-N02` ([`tests/test_nfr_performance.py`](../../tests/test_nfr_performance.py)) демонструє час відгуку `p95 ≤ 300 мс` (фактично ~80.3 мс) під навантаженням 50 одночасних користувачів на 500 активних оголошеннях із 0% помилок;

- Немає відкритих критичних або блокуючих дефектів (Critical/High);
- Публічні та анонімні відповіді містять рівно 0 контактних полів продавця (`SEC-002`).
