# План тестування — Baraholka NaUKMA

**Обсяг:** тестуємо реалізоване ядро оголошень: створення, публічний каталог із текстовим пошуком і фільтрацією, зняття з публікації та нерозкриття контактів анонімним користувачам. Для PERF-001 окремо плануємо системну перевірку API каталогу як серверної частини завантаження сторінки. Свідомо не тестуємо інші сценарії ще не реалізованих реєстрації й повної JWT-автентифікації, фотографій, обраного, історії продавця, адміністрування, React UI, реальної PostgreSQL та відновлення після збою. Повну перевірку PERF-001 разом із рендерингом React UI буде додано після появи клієнтського застосунку.

**Критерії виходу:** усі автоматизовані функціональні та security-кейси плану, крім `TP-N02`, проходять у CI; покриття `src/` не нижче 85%; немає відкритих критичних або високих дефектів; анонімні відповіді містять 0 контактних полів. `TP-N02` не входить до звичайного CI: його запускаємо окремо в контрольованому середовищі, а конфігурацію та результат фіксуємо у звіті тестування. До появи React UI успішний `TP-N02` підтверджує лише продуктивність API, а не повне виконання PERF-001 для сторінки.

**Ризики:** найбільший вплив мають обхід авторизації власника, витік контакту продавця, поява знятих оголошень у каталозі та деградація пошуку під навантаженням. Поточні API-тести використовують `InMemoryListingRepository` і тимчасовий заголовок `X-Actor-Id`, тому не доводять коректність PostgreSQL/JWT; створення оголошення поки не підтримує обов'язкові фотографії з FR-002; позитивний авторизований доступ до контакту за FR-010 ще не реалізовано; повна перевірка PERF-001 заблокована до появи React UI, а серверну частину перевіряємо окремим навантажувальним прогоном API.
