# План тестування — Baraholka NaUKMA

**Обсяг:** тестуємо реалізоване ядро оголошень: створення, публічний каталог із текстовим пошуком і фільтрацією, зняття з публікації та нерозкриття контактів анонімним користувачам. Для PERF-001 окремо плануємо системну перевірку завантаження сторінки каталогу. Свідомо не тестуємо інші сценарії ще не реалізованих реєстрації й повної JWT-автентифікації, фотографій, обраного, історії продавця, адміністрування, React UI, реальної PostgreSQL та відновлення після збою.

**Критерії виходу:** усі тест-кейси плану проходять у CI; покриття `src/` не нижче 85%; немає відкритих критичних або високих дефектів; анонімні відповіді містять 0 контактних полів; каталог із максимум 20 картками відповідає не довше ніж за 300 мс при 50 одночасних користувачах.

**Ризики:** найбільший вплив мають обхід авторизації власника, витік контакту продавця, поява знятих оголошень у каталозі та деградація пошуку під навантаженням. Поточні API-тести використовують `InMemoryListingRepository` і тимчасовий заголовок `X-Actor-Id`, тому не доводять коректність PostgreSQL/JWT; створення оголошення поки не підтримує обов'язкові фотографії з FR-002; позитивний авторизований доступ до контакту за FR-010 ще не реалізовано; повна перевірка PERF-001 заблокована до появи сторінки каталогу та середовища навантажувального тестування.
