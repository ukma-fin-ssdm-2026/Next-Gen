# План тестування — Baraholka NaUKMA

**Обсяг:** тестуємо реалізоване ядро оголошень: створення (включно з фотографіями через `ImageStorage` та станом товару `condition`), редагування власного оголошення, історію власних оголошень продавця (`ACTIVE` і `WITHDRAWN`), публічний каталог із текстовим пошуком і фільтрацією, зняття з публікації та нерозкриття контактів анонімним користувачам. Для PERF-001 окремо плануємо системну перевірку API каталогу. Свідомо не тестуємо ще не реалізовану Microsoft Entra ID / OIDC-автентифікацію, обране, адміністрування, React UI, реальну PostgreSQL та відновлення після збою. Повну перевірку PERF-001 разом із React UI буде додано після появи клієнтського застосунку.

**Критерії виходу:** усі автоматизовані функціональні та security-кейси плану, крім `TP-N02`, проходять у CI; покриття `src/` не нижче 85%; немає відкритих критичних або високих дефектів; анонімні відповіді містять 0 контактних полів. `TP-N02` не входить до звичайного CI: його запускаємо окремо в контрольованому середовищі, а конфігурацію та результат фіксуємо у звіті тестування. До появи React UI успішний `TP-N02` підтверджує лише продуктивність API, а не повне виконання PERF-001 для сторінки.

**Ризики:** найбільший вплив мають обхід авторизації власника, витік контакту продавця, поява знятих оголошень у каталозі та деградація пошуку під навантаженням. Поточні API-тести використовують `InMemoryListingRepository`, `InMemoryImageStorage` і `X-Actor-Id`, тому не доводять коректність PostgreSQL, зовнішнього хмарного сховища зображень, Microsoft Entra ID, OIDC callback чи локальної сесії; збереження фотографій за FR-002 наразі реалізовано на рівні метаданих `image_urls` в `InMemoryImageStorage` (без обов'язкового бінарного завантаження файлу); позитивний авторизований доступ до контакту за FR-010 ще не реалізовано; повна перевірка PERF-001 заблокована до появи React UI.
