# Високорівнева архітектура (High-Level Design)

## Архітектурний стиль

Для проєкту "Baraholka NaUKMA" обрано **Клієнт-серверну архітектуру (Client-Server)** із бекендом у формі **Моноліту (Monolithic API)**.

### Обґрунтування вибору:
1. **Простота розробки та розгортання:** Оскільки застосунок має відносно невеликий і чітко окреслений набір функцій (дошка оголошень для одного університету), мікросервісний підхід створив би невиправдані накладні витрати (overengineering) на мережеву взаємодію, DevOps та управління транзакціями. Моноліт дозволяє швидко доставляти фічі силами невеликої команди.
2. **Чіткий поділ відповідальності:** Клієнтський застосунок (React SPA) відповідає виключно за рендеринг інтерфейсу і взаємодію з користувачем, тоді як сервер (FastAPI) концентрує всю бізнес-логіку, валідацію і безпеку.
3. **Ефективність:** Зв'язок між компонентами бекенду відбувається через виклики функцій у пам'яті (in-process), що є найшвидшим можливим способом взаємодії, на відміну від HTTP-запитів між мікросервісами.

## Основні компоненти та їхня взаємодія

Система складається з трьох фізичних рівнів (Tiers), які відображені на компонентній діаграмі:

1. **Клієнтська частина (Frontend)**
   - **React SPA:** Завантажується в браузер користувача. Відповідає за відображення UI (каталог, форми, особистий кабінет). Взаємодіє з сервером через REST API, використовуючи HTTP/HTTPS та JWT-токени для авторизації.

2. **Серверна частина (Backend - FastAPI Monolith)**
   - **API Router (REST):** Єдина точка входу для всіх HTTP-запитів. Відповідає за маршрутизацію запитів до відповідних контролерів.
   - **Auth Service:** Відповідає за перевірку домену `@ukma.edu.ua`, хешування паролів, генерацію та валідацію JWT-токенів.
   - **Listing Service:** Керує логікою створення, редагування, фільтрації та пошуку оголошень (включаючи додавання в обране).
   - **Moderation Service:** Забезпечує функціонал для адміністраторів (зняття оголошень, блокування користувачів).
   - **ORM / Data Access Layer:** Абстракція (наприклад, SQLAlchemy) для взаємодії з базою даних, трансляції об'єктно-орієнтованих запитів у SQL та управління транзакціями.

3. **Сховище даних (Database)**
   - **PostgreSQL Database:** Реляційна база даних, яка забезпечує ACID-властивості для надійного зберігання сутностей (`User`, `Listing`, `Favorite` тощо).

## Інтерфейси між компонентами

- **React SPA ↔ FastAPI Server:** 
  - Протокол: `HTTP/HTTPS`.
  - Формат даних: `JSON` по REST.
  - Безпека: Передача JWT-токена в заголовку `Authorization: Bearer <token>`.
- **FastAPI Server ↔ PostgreSQL Database:**
  - Протокол: `TCP/IP` (PostgreSQL Wire Protocol).
  - Інтерфейс: SQL-запити, що генеруються ORM-рівнем.
