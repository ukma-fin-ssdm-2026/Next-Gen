## 4. Співпраця та робочий процес
- Стратегія гілкування: GitHub Flow - гілка на кожну фічу/задачу, коміт в main через pull request.
- Практики комітів: маленькі коміти; повідомлення у форматі `короткий опис` (напр. `додано розділ про CI`).
- Правила огляду коду: жоден PR не мерджиться без хоча б одного схвалення; автор PR не апрувить власний код.
- Робочий процес завдань: відкрити issue → призначити виконавця → працювати у гілці → відкрити PR, лінкований на issue → після апруву змерджити → закрити issue.

## 8. Використання ШІ
Керуємось Політикою використання ШІ курсу (розділ «Три обов'язки»: розумійте, верифікуйте, розкривайте).

- Інструменти: Claude, ChatGPT. Дозволені для чернеток коду, тестів, документації та рев'ю; заборонені для генерації фейкових результатів тестів чи джерел.
- Правила розкриття: кожен артефакт лабораторної містить коротку нотатку «Використання ШІ» — що згенеровано, на якому етапі, і що саме перевірено/відкинуто вручну. На пряме запитання викладача — відповідь точна, без applyприховування.
- Правило верифікації: будь-який згенерований код проходить ті самі кроки, що й написаний вручну — самоперегляд автором, тести, статичний аналіз, рев'ю іншим учасником команди. Неперевірений згенерований код у main не потрапляє.
- Персональні дані одногрупників і закриті матеріали курсу в зовнішні ШІ-сервіси не передаємо.
